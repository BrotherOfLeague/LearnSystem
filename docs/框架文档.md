# LearnSystem RAG 框架文档

> 本文档描述 LearnSystem 作为「RAG + LLM 问答框架」的架构、模块职责、接口抽象与扩展方式，便于理解和二次开发。

## 1. 定位

LearnSystem 是一个**轻量级 RAG（检索增强生成）问答框架**，用于「基于本地文档库的中文问答」。

核心思想：**不训练模型，用「检索」从文档库里捞出证据，再让 LLM 依据证据生成回答**，回答带可核查的出处链接。

三个关键设计原则：

1. **端到端可运行优先**：先打通「导入 → 分块 → 索引 → 检索 → 生成」全链路，再优化质量。
2. **接口隔离**：Embedding、向量库、LLM 均通过接口抽象，可替换实现。
3. **答案可追溯**：引用链接由程序从检索结果的元数据生成，不由 LLM 编造。

## 3. 数据流

### 3.1 离线索引流程（一次性）

```
Python 官方 HTML 文档（data/raw）
        │
        ▼
  DocumentLoader          识别 HTML、生成规范 URL、过滤重定向页
        │
        ▼
  HtmlParser              提取标题/章节路径/正文/代码块（保留换行与缩进）
        │
        ▼
  RuleBasedChunker        按段落/代码块边界切分，生成 chunk + 元数据
        │
        ├──► chunks.jsonl（调试产物）
        │
        ▼
  EmbeddingProvider       逐批生成向量（bge-m3，1024 维）
        │
        ▼
  ChromaVectorStore       持久化向量 + 元数据（storage/chroma）
```

增量更新：`import_docs` 用 `source_hash`（原始文件 MD5）检测变更，未变化的文档直接复用上次解析结果；`build_index` 在非 rebuild 模式下清理已删除文档的陈旧分块。

### 3.2 在线问答流程（每次提问）

```
用户中文问题
      │
      ▼
 Retriever ──► Embedding(问题) ──► 向量检索 Top-K
      │
      │（可选：BM25+RRF 混合 / 查询改写）
      ▼
 证据上下文（编号 + 原文 + 来源 URL）
      │
      ▼
 Prompt 组装（含对话历史、证据、回答规则）
      │
      ▼
 LLMClient.generate / generate_stream
      │
      ▼
 回答 + 引用来源 ──► 返回前端（一次性 / SSE 流式）
```

## 4. 核心模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 配置 | `config/settings.py` | Pydantic Settings，读 `.env` |
| 文档模型 | `models/document.py` | `Document` / `ParsedDocument` / `ImportStats` |
| 分块模型 | `models/chunk.py` | `Chunk`（含元数据、`to_embedding_text`、`to_metadata`） |
| 加载器 | `loaders/document_loader.py` | 遍历 HTML、生成 URL、过滤噪声页 |
| 解析器 | `parsers/html_parser.py` | 提取标题/章节/正文/代码块 |
| 分块器 | `chunker/rule_based_chunker.py` | 按段落+代码块边界切分，支持目标长度/重叠 |
| Embedding | `embedding/local.py` | bge-m3 向量化，自动 CUDA(fp16)/CPU |
| 向量库 | `retriever/chroma_store.py` | Chroma 读写、upsert、按文档删除 |
| 检索器 | `retriever/retriever.py` | 向量检索（`retrieve` / `retrieve_batch`） |
| RAG 引擎 | `retriever/rag_engine.py` | 检索 → 拼 Prompt → LLM 生成 → 提取引用 |
| LLM | `llm/openai_client.py` | OpenAI 兼容客户端（`generate` / `generate_stream`） |
| 评估 | `evaluation/` | 30 题评估集 + Recall@5/MRR 指标 |

## 5. 接口抽象（可替换点）

框架通过 `Protocol` / `ABC` 定义了三个核心抽象，业务层只依赖接口：

### 5.1 EmbeddingProvider

```python
class EmbeddingProvider(Protocol):
    @property
    def model_name(self) -> str: ...
    @property
    def dimension(self) -> int: ...
    def embed(self, text: str) -> list[float]: ...
    def embed_batch(self, texts: list[str]) -> list[list[float]]: ...
```

### 5.2 VectorStore

```python
class VectorStore(Protocol):
    def add_chunks(self, chunks, embeddings) -> int: ...
    def search(self, query_embedding, top_k) -> list[SearchResult]: ...
    def count(self) -> int: ...
    def delete_by_document_ids(self, document_ids) -> None: ...
    def clear(self) -> None: ...
```

### 5.3 LLMClient

```python
class LLMClient(Protocol):
    @property
    def model(self) -> str: ...
    def generate(self, prompt, **kwargs) -> LLMResponse: ...
```

### 5.4 Retriever（策略层）

检索器有多种策略，接口统一为 `retrieve(query, top_k) -> list[SearchResult]`：

- `Retriever`：纯向量检索（当前默认，基线 Recall@5=0.7667）
- `HybridRetriever`：向量 + BM25，RRF 融合（评估后不启用）
- `RewriteRetriever`：查询改写增强（评估后不启用）

## 6. 服务化 API（Django + DRF）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/chat/` | 提问（一次性返回回答+来源，带 `conversation_id` 支持多轮） |
| POST | `/api/chat/stream/` | 提问（SSE 流式，逐字返回） |
| GET/POST | `/api/conversations/` | 会话列表 / 新建 |
| GET | `/api/conversations/{id}/` | 会话详情（含消息） |
| GET | `/api/health/` | 健康检查 |

RAG 引擎在 `backend/chat/services.py` 中以**全局单例**懒加载，模型只加载一次（约 1.1GB 显存），并发请求复用同一实例。

## 7. 关键设计决策

| 决策 | 理由 |
|---|---|
| 检索用本地 bge-m3，生成用远程 LLM | 跨语言语义检索强（中文问题→英文文档），生成走 API 免运维 |
| 向量库用 Chroma | POC 单机够用；接口已抽象，后续可换 pgvector/ES |
| 混合检索(BM25+RRF)不启用 | 评估显示略逊于纯向量（高频函数名噪声） |
| 查询改写不启用 | MRR 仅 +0.017，每问 +1.85s 延迟不划算 |
| 服务化用 Django DRF（非 FastAPI） | 用户指定，接口能力等价 |

## 8. 扩展指南

**接入新文档源**：实现新的 Loader + Parser，产出 `ParsedDocument`，复用 Chunker/Embedding/VectorStore。

**换 Embedding 模型**：实现 `EmbeddingProvider`，改 `.env` 的 `EMBEDDING_MODEL`。

**换向量库**：实现 `VectorStore`（`add_chunks` / `search` / `count` / `delete_by_document_ids` / `clear`），替换 `ChromaVectorStore`。

**换 LLM**：实现 `LLMClient`，改 `.env` 的 `LLM_BASE_URL` / `LLM_MODEL`（OpenAI 兼容协议通用）。

**换检索策略**：实现 `retrieve(query, top_k)`，在服务层替换 `Retriever` 实例。
